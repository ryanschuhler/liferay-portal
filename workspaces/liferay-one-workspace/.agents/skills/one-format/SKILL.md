# Format Source

Run all six steps from the workspace root (`workspaces/liferay-one-workspace`). Stop when a step fails. Report the error. Do not run the next step.

## 1. Gradle source formatter

This step formats the Java files, the YAML files, and the other files outside the frontend:

```bash
./gradlew formatSource
```

## 2. ESLint (auto-fix)

```bash
yarn lint:fix
```

## 3. Prettier (auto-format)

```bash
yarn format
```

## 4. Stylelint

```bash
yarn lint:css:fix
```

## 5. SpotBugs

This step runs static analysis on the Java code. The step only reports. It writes no file.

```bash
./gradlew :client-extensions:liferay-one-etc-spring-boot:spotbugsMain
```

Read `.agents/rules/spring-boot-analysis.md` for the coverage of this step and for the open findings.

## 6. Structure checks

Two checks need the complete import graph. ESLint reads one file at a time, so ESLint cannot make these two checks. The first check finds an undeclared dependency and an unused dependency. The second check finds a component in a folder that its consumers do not agree with:

```bash
yarn lint:structure
```

These checks only report. They write no file, so they act the same way in check-only mode. They cover the dependencies, the component placement, the import graph, and the order of the entries in the batch JSON files. Read `.agents/rules/custom-element-structure.md` for the rules that they enforce and for the open counts.

## Check-Only Mode

Run the check command for each step above when the user invokes `one-format --check`. Each check command writes no file. Report the violations. Do not correct them. A caller with a read-only rule can therefore still verify the formatting completely.

| Step | Fix | Check |
| --- | --- | --- |
| 1. Gradle source formatter | `./gradlew formatSource` | `./gradlew checkSourceFormatting` |
| 2. ESLint | `yarn lint:fix` | `yarn lint` |
| 3. Prettier | `yarn format` | the command of the `format` script, with `--check` in place of `--write` |
| 4. Stylelint | `yarn lint:css:fix` | `yarn lint:css` |
| 5. SpotBugs | — | `./gradlew :client-extensions:liferay-one-etc-spring-boot:spotbugsMain` |
| 6. Structure checks | — | `yarn lint:structure` |

Each check exits with a value other than zero when it finds a violation. Each check names the file and the rule. Report every violation. Correct no violation. Never run the command that writes files after a check fails. A failed check is the answer.

Do not use this mode to run the formatter and then undo the changes. The formatter changes the tree, and the undo step restores the files from the index. That restore deletes the work that you did not commit. A failure between the two steps leaves changes in the tree. These checks write no file, so there is nothing to undo.

## Manual rules

Apply the manual rules in `.agents/rules/code-style.md` after the tools run. Run steps 2 to 4 again after each manual edit, so that the formatters clean those edits.

Skip every generated file. A generated file holds `@generated`, `$ANTLR`, `# This is a generated file.`, or `## Autogenerated`.
